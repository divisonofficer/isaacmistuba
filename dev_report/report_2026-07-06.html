A4. 왜 metallic 을 안 쓰는가 — 설계 근거

metal-vs-dielectric 판정은 오직 optical_class/bsdf_strategy 로 이뤄지며, metallic 스칼라는 렌더 제어에 한 번도 읽히지 않는다(UI 리포트·override 전달용으로만 READ).

  • 원본이 신뢰 불가: 진짜 금속조차 Principled Metallic 을 0으로 두는 경우가 태반(brushed_metal=0.0). 절차적 그래프가 Anisotropic/Glossy 로 금속 룩을 만들기 때문.
  • 이름 기반이 더 견고: shader_brushed_metal, shader_metal.* 이름 키워드가 metallic 스칼라보다 안정적. metallic≥0.5 는 보조 fallback.
  • 결과: metallic 이 0이어도 metal 은 conductor(Al η,k)로 정확히 렌더. metallic 채널만 보면 고장난 듯하지만 파이프라인상 무해.

B1. 편광 시각화 개편 (전역)

편광 산출물 PNG는 모두 modules/mitsuba_converter/src/mitsuba_converter/multimodal.py의 save_polarization_products()에서 생성된다. 두 가지를 고쳤고, 프로덕션 렌더 전체에 반영된다.

(a) Stokes S1/S2 → 순수 red-white-blue (배경 제거)

기존 bwr_map()은 발산형 red/blue 뒤에 S0 intensity(grayscale) 배경을 15% 하한으로 블렌딩했다. 이 때문에 부호(+/−)·크기가 밝기와 섞여 읽혔다. 이제 배경을 깔지 않고 0에서 흰색, +scale에서 순수 빨강, −scale에서 순수 파랑으로만 매핑한다(무효 픽셀은 흰색 fallback). S1/S0·S2/S0 도 동일.

(b) AoLP → 완전 DoLP-gating (hue 누출 제거)

aolp_map()의 hue 불투명도는 √DoLP 로 변조되지만 0.20 하한이 있어, DoLP≈0(무편광) 영역에서도 노이즈성 각도(hue)의 20%가 새어 나왔다. 하한을 제거해 rgb = context·(1−√DoLP) + hue·√DoLP 로 바꿔, 무편광 영역은 grayscale(S0)로 완전히 회귀하고 편광이 실재하는 곳에만 색이 남는다.

검증: 합성 Stokes 텐서로 확인 — +S1→(1.0,0.4,0.4) 빨강, −S1→(0.4,0.4,1.0) 파랑, DoLP≈0→(1,1,1) 순백(S1/S0); AoLP 는 고DoLP 블록에서 채도 hue, DoLP≈0 블록에서 (1.0,0.97,0.97) 회백 = hue 완전 억제. 실 렌더(§2)에서도 재확인.

B2. 재질 팔레트 재현 — spp 1024, 새 viz

통제된 "금속 팔레트"(plastic + 실금속 Al/Au/Cr/Ag/Cu 구)를 프로덕션과 동일한 render_modalities 경로로 spp 1024에서 재현. 각 재질이 서로 다른 DoLP/AoLP 서명을 갖는다는 것이 per-material IOR/eta·k 주입이 필요한 물리적 근거다. 새 viz 로 AoLP 의 specular highlight 중심이 회색으로 gating되고 DoLP 는 순백 배경 위에 읽힌다.

B3. 재질별 RGB↔편광 closeup — "이 재질은 RGB에선 이렇게, 편광에선 이렇게"

실내 전체 뷰포인트는 한 재질의 편광 서명이 주변 지오메트리에 묻힌다. 그래서 신규 도구 apps/render_material_closeups.py는 광학적으로 흥미로운 오브젝트를 하나씩 가까이 프레이밍한다: baked mesh 의 world bbox 를 읽어 오브젝트가 화면의 ~55%를 채우도록 카메라 거리를 잡고, 카메라 높이를 편안한 시야 band [0.9, 1.6] m 로 두어(floor/ceiling skimming 방지) 오브젝트를 내려다/올려다본다. 씬 자체 조명이 어둡고 불균일하므로 카메라 옆 fill point light(headlight, intensity ∝ dist²) 를 주입해 일관되게 밝힌다. injected(물리) 모드를 편광 variant 로 spp 1024 렌더하고 [RGB | DoLP | AoLP | S1/S0] montage 를 낸다. injected XML 은 프로덕션 render_scene.xml(갱신본) 재사용으로 ~7분 재생성 생략.

선택 기준: injected BSDF 가 metal(roughconductor)·glass(dielectric)·mirror(conductor)인 오브젝트(kr20260625 에 40개)를 고립도(최근접 이웃 거리) 우선·크기로 랭크. 단 납작한 오브젝트(벽거울·패널, min/max extent<0.3)는 제외 — 정면 법선 프레이밍이 없으면 비스듬히 보여 얇은 sliver 로만 잡힌다(초기 시도에서 확인). 결과적으로 잘 고립된 금속 가전·화분·유리 병이 선택됨.
디버그 히스토리 — 초기 렌더의 검은 영역은 physics 가 아니라 setup 버그였다. (1) 카메라 높이 버그: 예전 eye_y = center_y + 0.35·r 은 바닥 오브젝트에서 카메라를 ~0.2 m(바닥 skimming)에, 선반 위 병에선 천장 근처에 뒀다 → 프레임 하단/상단이 통째로 어두운 바닥·천장. (2) ambient no-op: _inject_constant_emitter 는 not _has_emitter 일 때만 작동하는데 이 씬엔 이미 emitter(area 15 + constant 0.57)가 있어 --ambient 가 완전히 무시됐다 → 유리/거울이 어두운 방을 비춰 검게 나옴. 해결: 높이 band clamp + 카메라 headlight. max_depth=6 은 유리/거울 1-bounce 에 충분하므로 검정의 원인이 아니었다.
A6 clamp 선행조건 — 이미 충족: roughness→alpha 는 _clamp_bsdf_alpha(ceiling=0.9)(render_daemon.py:1171)로 이미 clamp 되어 프로덕션 render_scene.xml 의 scalar alpha 는 max 0.6·>1 값 0개. snake_plant=14.28 은 잎(diffuse)이라 이 closeup 대상(금속·유리 용기/가전)에 없음. → 그대로 배치 렌더.
RGB tonemap — montage RGB 는 원본 rgb.png(specular percentile 자동노출) 대신 linear HDR(stokes_data.npz['rgb']) 에서 p90 을 일정 중간톤으로 맞추는 노출 + Reinhard + sRGB gamma 로 재-tonemap(도구 기본값). headlight 로 이미 잘 밝혀진 위에 적용되어 어두운 그림자까지 균형있게 보인다. DoLP/AoLP/S1·S0 패널은 물리량이라 그대로.
UV 수정 반영: 아래 closeup 은 §B8 exporter UV 수정 후의 메시로 재렌더했다 — 무-UV barycentric 아티팩트(가짜 텍스처)가 제거되어 텍스처가 올바르게 매핑된다(예: #2 나무결).

B4. kr20260625 갤러리 재렌더 — 갱신 카메라(FOV 75) + injection

B5. 편광 물리 검증 — vp_000030 침실 사례 (금속 vs 유전체)

§B4 #4(vp_000030) 를 자세히 뜯어보면 4가지 관찰이 나오는데, 전부 물리적으로 옳은 렌더임을 analytic Fresnel 로 정량 확인했다. 장면: 침대(천 침구) + 나무 등받이 + 등받이 위 은색 풍선(BalloonFactory). 재질 확인 — 풍선 shader_brushed_metal→roughconductor(Al), 등받이 shader_wood·침구 sofa_fabric→pplastic(diffuse).

단일 specular 반사의 DoLP — 유전체 vs Al 금속 (analytic Fresnel)

유전체 n=1.5 (유리/코팅)1.00 (Brewster 56°)0.830.98강편광

#관찰검증 (verdict)
1풍선 색 정보가 injection 후 변함 의도됨. legacy(코팅형 처리)→injected(실 Al η,k) 로 풍선이 제대로 반사(chrome-like). "색"은 고정 albedo 가 아니라 반사된 방이다. η,k 주입의 정상 효과.
2나무 등받이 편광이 injection 후 ≈0 의도된 교정. legacy 는 int_ior=1.5 를 전 표면에 발라 무광 나무까지 과편광(벽 corridor 와 동일). injected 는 rough diffuse 유전체로 두어 specular 편광 lobe 가 약·넓음→저DoLP. 단 analytic diffuse 편광은 1차 근사(Kondo 2020) — 실제 무광 나무는 약하지만 nonzero; "정확히 0" 은 모델 바닥이라 measured 는 잔차 존재.
3침구가 약한 편광 방출 타당(1차 근사). rough pplastic → 약한 DoLP + 주름 법선을 따라가는 AoLP(기하학적으로 옳음). 단 실제 직물은 subsurface·섬유 구조로 measured pBRDF 가 크기·분포에서 달라짐 — analytic 은 경향만.
4풍선이 RGB 는 glossy 인데 S1 편광이 안 보임 물리적으로 옳음. gloss(고반사) ≠ 고편광. Al 은 약편광(위 표: @45° DoLP 0.03) — 유리(0.83)의 1/28. 곡면 풍선의 다양한 각도에서도 DoLP 는 최대 0.14. 금속 vs 유전체 편광 구분의 교과서적 예.
한 줄: legacy→injected 의 "풍선 반사 강화 · 나무/침구 과편광 붕괴 · 금속 저DoLP" 는 모두 metal(약편광) vs dielectric(강편광, 무광이면 저편광) 의 올바른 물리다. 남는 정량 오차는 analytic diffuse 의 태생적 한계(measured pBRDF 영역)로, §7-01 로드맵과 동일.

B7. Infinigen 오브젝트 종류 × 재질 signature → 편광 준비도 · 텍스처 소비 현실

Infinigen indoor 가 실제로 어떤 종류의 오브젝트를 만들고, 각 오브젝트가 어떤 재질 채널을 들고 오는지(UV / albedo / roughness / metallic / IOR, 그리고 각 맵이 공간변화(spatially-varying)인지 스칼라인지)를 전수 스캔했다. 관찰의 출발점: bookshelf·bottle 류는 UV·albedo·roughness 가 다 있고 metallic 도 공간변화로 있는데, glass bottle 은 albedo·roughness·metallic·UV 가 아예 없고(순수 IOR), fabric 은 UV 없이 flat albedo 만 있다 — 이 채널 유무 패턴이 곧 광학 클래스이자 편광 렌더 준비도라는 가설을 데이터로 확인한다.

스캔 방법. import 2개(kr_20260627 598 + kr_88074926_apartment 605 = 1,203 objects)에 대해 ① mesh .obj 의 vt 유무로 UV, ② baked {oid}_{albedo|metallic|roughness|normal}.png 존재+std>0.04 로 맵·공간변화, ③ scene_manifest.json 의 optical_class / ior / is_glass / metallic·roughness scalar 를 결합. 스크립트: apps/analyze_infinigen_material_signatures.py.

렌더타임 현실 — shared BSDF + 텍스처 소비 3분류 (per-file 스캔의 보정)

위 per-file signature 는 두 가지를 놓친다: (1) 렌더 파이프라인은 같은 재질을 쓰는 인스턴스끼리 BSDF·텍스처를 공유(kr_20260627 기준 distinct textured shared_bsdf 521개가 1,087 shape 을 커버)하므로, 자기 baked 파일이 없는 인스턴스도 대표 인스턴스의 텍스처로 렌더된다 → flat 과다계상. (2) 텍스처가 BSDF 에 바인딩돼도 메시에 UV(vt)가 없으면 소비 불가. 그래서 render_scene.xml 의 실제 placed shape 1,978개(3 씬)를 다시 파싱해 각 shape 의 주입된 BSDF 광학타입 × 텍스처 바인딩 × mesh_cache UV 를 뽑았다. 근본 원인 & 수정 — export/bake 순서 버그 (upstream, 채택)

UV 손실의 진짜 원인은 tools/infinigen/blender_export_scene.py 의 export/bake 순서였다. Blender 씬에서 무-UV 오브젝트(TVStand·Cabinet·Shelf: uv_layers=0)는 —

  1. 메인 루프가 OBJ 를 먼저 export(_export_obj) → 이 시점엔 UV 없음 → vt=0.
  2. 그 뒤 bake 단계의 _ensure_uv 가 Smart-UV-project 로 UV 를 생성 → 그 UV 로 atlas 를 굽는다.
  3. GLB 는 bake 후 export → GLB 만 그 UV 를 담고, OBJ 는 못 담는다.

결과: atlas 는 OBJ 에 없는 UV 로 구워져, 렌더 시 mitsuba 가 barycentric per-triangle fallback 으로 atlas 를 적용 → 가짜 반복 텍스처(TVStand 가 나무결이 아니라 가짜 houndstooth "직조"로 보였던 이유). 즉 §B4/§B3 에서 무-UV 금속에 보이던 "디테일" 은 아티팩트였다.

수정(1줄): _ensure_uv(obj) 를 _export_obj 앞에 호출 → OBJ 와 bake 가 같은 Smart-Project UV 를 공유. flag 불필요, 표준 OBJ 경로가 바로 옳게 동작. 검증: TVStand 재-export → OBJ vt=0→1090, 2D UV [0.01,0.97]×[0.01,0.99], 렌더가 올바른 나무결(아래).

속도: re-bake 불필요 (Smart-UV 결정성) → ~5분 적용

Smart-UV-Project 가 결정적(같은 mesh+params → 같은 UV)임을 확인: no-bake 재-export UV == with-bake UV(동일), 그리고 no-bake OBJ + 원본 production atlas 렌더가 올바름. 즉 기존 atlas 는 이미 이 결정적 UV 로 구워졌고, OBJ 만 그 UV 를 못 담았던 것. → re-bake 불필요. 신규 --reuse-atlas 모드로 OBJ 만 재-export + MTL 을 기존 atlas 에 재연결.

적용 완료(kr20260625, in place): --reuse-atlas --no-bake 로 263 obj ~5분 재-export(bake 없음). atlas 있는 no-UV 오브젝트 72→0(전부 교정), TVStand vt=0→1090. 남은 no-UV 55개는 atlas 없음(mirror/glass/미-bake) → UV 무의미. 표준 OBJ 경로가 flag 없이 올바르게 동작(GLB 라우팅 대안은 유지, flag OFF).
변경: tools/infinigen/blender_export_scene.py(_ensure_uv before export + --reuse-atlas/--only), render_daemon.py·glb_texture_adapter.py(GLB 경로 대안).
