2024 · Princeton Vision & Learning Lab · Infinigen 자연 장면 후속 연구

실내 에셋 라이브러리가 아니라,
인공물 생성 규칙과 실내 배치 제약의 결합 시스템이다.

왜 Infinigen의 후속 연구가 필요했나

Infinigen 2023 (CVPR) — 무엇을 해결했나

핵심 성취
  • 자연 세계를 외부 에셋 없이 100% 절차적으로 생성
  • 182개 자연물 생성기 (지형·식물·동물·날씨·유체)
  • 1,070개 무작위화 가능 파라미터
  • Node Transpiler: 아티스트 노드 그래프 → Python 코드
  • 실제 메쉬 기반 기하 → depth/normal 정답 신뢰 가능
무엇이 빠져 있었나
Infinigen 2023은 자연 장면 중심이었다. 숲, 해안, 사막, 수중은 생성할 수 있지만, 거실·주방·화장실·사무실·복도·계단 같은 인간이 설계한 실내 공간은 다루지 않았다.

왜 실내 데이터가 중요한가

로봇과 증강현실이 실제로 작동하는 공간은 자연 숲이 아니라 거실, 주방, 화장실, 사무실, 계단이다.

"자연 장면만으로 foundation model 학습이 충분할 수 있다"는 가설은 아직 증명되지 않았고, 응용 도메인에 가까운 합성 데이터가 더 좋은 downstream 성능을 낼 가능성을 시사한다.
기존 실내 합성 데이터셋의 한계
대부분이 정적 3D 에셋 라이브러리에 의존. 일부는 floorplan만 절차적으로 만들 뿐, 오브젝트·재질은 고정 에셋. → 다양성 상한 = 라이브러리 크기

핵심 주장 — 실내도 100% 절차적으로 생성할 수 있는가

중심 명제: 미리 만들어진 의자·책상·냉장고 모델을 골라 배치하는 것이 아니다. 의자가 어떻게 구성되는지, 방 안에 어디에 놓이는지를 규칙으로 코드화했다. 인공물은 자라는 것이 아니라 부품과 설계 치수의 조합으로 생성된다.

자연물 vs 인공물 — 생성 방식의 차이

자연물 생성 (Infinigen 2023)
나무 생성: skeleton 생성 (무작위 성장 규칙) ↓ skinning (골격에 메쉬 씌우기) ↓ 잎 배치 (공간 점유 알고리즘) ↓ 재질 (나무껍질·잎 절차적 셰이더)
핵심 법칙: 성장과 물리적 형성
인공물 생성 (Infinigen Indoors)
의자 생성: 좌석 메쉬 생성 (크기·모양 파라미터) ↓ 등받이 (높이·기울기·패딩 여부) ↓ 다리 (개수·형태·두께) ↓ 팔걸이 (유무·높이·소재) ↓ 재질 (패브릭·가죽·금속 파라미터)
핵심 법칙: 부품 구성과 설계 치수

79개 절차적 오브젝트 생성기 — 인공물을 규칙으로 만들기

각 생성기는 Blender Geometry Nodes, modifier, mesh manipulation으로 구현된다. 아티스트 노드 그래프 기반 생성 원칙(Infinigen의 Node Transpiler 철학)을 계승한다.

가전 (10개) 냉장고, 오븐, 세탁기, 전자레인지, 식기세척기, 에어컨 등.

패널 + 손잡이 + 다이얼 같은 구성 요소 조합. 문 여닫이 articulation 포함. 크기·색·손잡이 형태 파라미터화.
문·창문·계단 (14개) 문·창문: 패널을 mesh boolean 연산으로 잘라내 프레임과 개구부 생성.

계단: atomic component(발판+난간)의 array repetition. 난간 세부 형태, 발판 높이, 단 수 파라미터화.
가구 (17개) 의자: 좌석·등받이·다리·팔걸이·쿠션 두께·곡률 파라미터.

소파·책상·선반·서랍장·침대·옷장 등. 각 카테고리별 구성 요소 분리 + 재질 분리.
장식 (15개) 그림 액자, 화분, 조명 기구, 시계, 책 묶음, 수납함 등.

소형 조합 구조. 조명은 실제 emitter로 동작. 책 묶음은 개별 책 생성기 반복 배열.
소형 물체 (19개) 컵·접시·병·식기·포장지 등 소품.

담요·베개: soft-body collision sim으로 축 처짐 형태.
풍선·포장지: cloth sim으로 공기 넣은 형태.

물리 시뮬레이션을 활용한 형태 생성

Soft-body collision simulation: 담요, 베개, 접힌 옷처럼 중력에 의해 변형된 부드러운 물체. 평평한 천을 시뮬레이션해 늘어진 형태를 물리적으로 만든다. 단순 파라미터화로는 표현하기 어려운 자연스러운 변형이 가능.
Cloth simulation: 풍선처럼 내부 압력이 있거나 포장지처럼 표면이 들뜬 형태. 파라미터화된 고정점에 옷감 물리를 적용해 생성. 매번 다른 주름과 접힘 패턴.

왜 실내 재질이 어려운가

자연물에서 중요한 재질이 흙·바위·나무껍질·식물 표면이었다면, 실내에서는 목재 가구, 금속 손잡이, 세라믹 세면대, 패브릭 소파, 플라스틱 포장지처럼 완전히 다른 재질 분포가 중요해진다.

단순히 "오브젝트 종류가 늘었다"가 아니라, 실내 장면을 구성하는 재질 분포 자체를 새로 확장한 것이다.

제약 기반 배치 — Python API로 실내 상식 표현하기

이것이 Infinigen Indoors의 진짜 신규 기여다. 오브젝트와 재질 생성 자체는 Infinigen의 절차적 철학 연장이지만, "어디에 어떻게 놓는가"는 완전히 새로운 문제다.

논문: "실내 배치는 에르고노믹스, 미학, 기능성을 따르는 복잡한 규칙을 가진다. 같은 테이블도 공부방에서는 벽에 붙어 있지만, 식당에서는 벽에서 떨어져 의자에 둘러싸여야 한다."

Constraint API 예시

# 식탁과 의자 배치 제약 (논문 그림 9 기반)
table = place(DiningTable, on=floor,
              params={"width": sample(1.2, 2.0),
                      "seats": sample_int(4, 8)})

chairs = place(Chair,
               count=table.seats,
               constraint=[
                 symmetric_around(table),
                 clearance(table, min=0.6),
                 face_toward(table)])

# 냉장고 접근 공간 확보
fridge = place(Refrigerator, on=floor,
               constraint=[against_wall(),
                           free_space_front(min=1.0)])
사용자는 선언적으로 "좋은 배치가 무엇인가"를 정의한다. 솔버가 이를 만족하는 구체적 배치를 찾는다.
핵심: 자연 장면에서는 나무가 무리 짓고 바위가 지면에 있는 분포가 직관적이었다. 실내에서는 이 상식적 제약을 코드로 명시해야 한다. Constraint API는 그 명시의 언어다.

배치 솔버 — Simulated Annealing으로 가구와 소품 배치 찾기

제약을 쓴다고 끝나는 게 아니다. 방 안 오브젝트 수가 많아지면 가능한 배치 공간이 너무 커진다. 솔버는 Simulated Annealing + Metropolis-Hastings 기준으로 탐색한다.

제안 Move 종류

  • 추가 / 삭제 — 오브젝트를 장면에 넣거나 제거
  • 관계 변경 — 다른 support plane으로 이동 (바닥 → 선반 위 등)
  • 파라미터 재샘플링 — 오브젝트의 크기·형태 재생성
  • Pose 재초기화 — 위치·회전 완전히 새로 배치
  • 이동 — 현재 위치에서 작은 이동
  • 회전 — 현재 방향에서 작은 회전

계층적 최적화 + 자유도 제한

1단계: 큰 가구 (소파·책장·침대) → 방 전체 공간 고려, 이동 자유도 2D 2단계: 중간 오브젝트 (의자·탁자·램프) → 큰 가구와의 관계 제약 추가 3단계: 작은 소품 (컵·책·장식) → 상위 오브젝트 위에 고정 예: 책장이 벽에 기대어 있으면 이동 자유도 = 벽과 바닥이 만나는 1D 선
중요: 오브젝트 파라미터도 최적화 대상. "이 방 크기에 맞는 식탁 크기"까지 함께 결정.

최적화 기법

BVH Caching
충돌 검사에 사용하는 BVH(Bounding Volume Hierarchy)를 캐시. 오브젝트가 이동하면 해당 부분만 업데이트.
Plane Hashing
support plane 탐색을 해시 구조로 가속. "컵을 놓을 수 있는 수평면"을 빠르게 조회.
전체 속도
3×
최적화 적용 후 비최적화 대비 속도 향상

Floorplan 생성 — 방 연결 그래프와 다층 건물 구조

생성 흐름

house outline (랜덤 다각형) ↓ Mondrian Process 공간 분할 (방들에 충분한 공간 할당) ↓ room adjacency graph 생성 (방 종류·연결성 그래프) └─ probabilistic CFG로 추론 └─ 또는 사용자 입력에서 부분/전체 지정 ↓ simulated annealing 최적화 목적 함수: - 방 면적 / aspect ratio - convexity (볼록 형태 선호) - 출입구까지 최단 경로 - 좁은 통로 최소화 - 계단 점유 면적 ↓ 바닥·벽·천장·문·창문·계단 생성 ↓ 방 유형별 가구·소품 배치

다층 건물 지원

층 구조
0층, 1층, 2층으로 분리된 다층 floorplan 생성. 계단이 인접 층을 연결. 계단 점유 면적이 각 층 최적화 목적 함수에 포함된다.
Room Adjacency Graph
방 유형(거실·주방·침실·화장실·복도)과 연결성을 나타내는 그래프. Probabilistic Context-Free Grammar로 상식적인 방 배치 분포를 학습. 사용자가 원하는 방 구성을 부분 또는 전체로 지정 가능.
Mondrian Process
직사각형 공간을 재귀적으로 분할하는 확률 과정. 각 방이 충분한 면적을 가지도록 초기 공간 분배. 이후 SA 최적화로 실제 방 경계 확정.

실시간 시뮬레이터 Export — Isaac Sim / Unreal Engine 연결

Infinigen Indoors는 Blender 안에서 장면을 생성하지만, 이를 실시간 로봇 시뮬레이터로 연결하는 export 도구를 함께 제공한다.

절차적 재질 → 표준 텍스처 맵
Blender 절차적 셰이더는 타 시스템과 portable하지 않다. UV mapping + texture baking으로 변환:
color, roughness, metallicity, normal 맵으로 bake. 이후 표준 PBR 파이프라인으로 사용 가능.
Isaac Sim (Omniverse)
URDF 자동 생성 (collision geometry + articulation 정보).
단일 오브젝트 OBJ/FBX/STL export.
RTX 4090 기준 대화형 프레임레이트 확인 (논문 그림 12).
Unreal Engine 5
같은 baked 텍스처 맵 사용.

Geometric Diversity ≠ Optical Diversity

Infinigen Indoors는 형태와 배치의 다양성을 해결했다.
그러나 유리문, 금속 손잡이, 세라믹 타일이
편광 카메라 · NIR 센서에 어떻게 보이는지는 전혀 다른 문제다.
Blender Cycles는 RGB photo-realistic 렌더링 시스템이다. 물리 기반 렌더링을 표방하지만, 이는 "인간 눈에 사실적으로 보이는" 기준이다. 편광 상태, NIR 파장 반사율, 분광 응답 같은 센서 모달리티별 광학 물리는 모델링되지 않는다.
