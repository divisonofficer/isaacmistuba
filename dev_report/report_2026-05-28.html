Sensor 모드 — 실제 USD 3D 씬 위에 버텍스그래프 오버레이 (200n · 204e) — DTC 에셋(소파·의자·조명 등)이 실제 3D 형태로 렌더되고, 주황 노드 200개 + 파란 삼각 엣지 204개가 자동 생성됨. 오른쪽 패널: Grid ready → Graph ready (200n 204e) → Episodes 생성 (train 120 / val_seen 20 / val_unseen 20).

node_sampler.py — 핵심 알고리즘

sample_viewpoint_nodes(
    grid: TraversabilityGrid,
    *,
    max_nodes: int = 300,
    heading_count: int = 12,   # 방향별 360°/12 = 30° 스텝
    min_node_spacing_m: float = 0.5,
    min_clearance_m: float = 0.0,
    seed: int = 0,
) → list[ViewpointNode]

# 알고리즘:
# 1. traversable 셀 목록을 랜덤 셔플
# 2. 각 후보 셀: clearance_m 계산 (가장 가까운 obstacle 거리)
# 3. 이미 선택된 노드와 min_spacing 초과인 것만 채택
# 4. 각 노드에 12방향 ViewpointHeading 자동 부착
# → ViewpointNode list 반환

뷰포인트 노드 + 방향 + 관측 링크 그래프

데이터 구조

ViewpointNode
  node_id: str
  position: [x, y, z]
  clearance_m: float
  tags: list[str]
  headings: list[ViewpointHeading]

ViewpointHeading
  heading_id: str
  yaw_deg: float
  sensor_observations: dict[str, str]

    # value: 렌더 출력 경로

ViewpointEdge
  source: str
  target: str
  weight: float
  has_hazard: bool
  passage_type: str  # "open"|"glass_door"|...

4-시나리오 에피소드 샘플러

시나리오경로 선택 규칙
goal_only 최단 경로로 목표 도달. 위험 무시.
hazard_aware 유리/거울 통과 경로를 포함하되 에피소드에 hazard_crossing=true 기록.
stop_before_glass 유리문 앞 노드를 goal로 설정. "유리를 만나면 멈춰라" 지시문 생성.
detour 위험 구역 우회 경로. "안전한 우회로를 통해 이동하라" 지시문 생성.
핵심: stop_before_glass와 detour는 OpticalNav 고유 시나리오 — 기존 VLN 벤치마크에 존재하지 않는다.

SensorSweep — 뷰포인트별 렌더 요청 생성

build_sweep_render_requests(graph, scene_id, modalities, spp, resolution)
  → list[SweepRenderRequest]
      node_id + heading_id + RenderRequest (→ render_daemon POST /render)

각 노드의 각 방향(yaw_deg)에 대해 mat4 카메라 변환 생성 후 렌더 요청.
결과 EXR 경로를 heading.sensor_observations[modality]에 기록.
→ write_viewpoint_graph()로 저장.

pageMode 전환 로직

// setPageMode() — 모드별 사이드이펙트 처리
async function setPageMode(mode: PageMode) {
  if (mode !== 'sim') stopRobotAnimation();
  pageMode = mode;

  if (mode === 'sim') { startRobotAnimation(); }

  // Paths / Sensor 모드 진입 시 그래프가 없으면 자동 로드
  if ((mode === 'paths' || mode === 'sensor') && !graphPayload && hasGraph) {
    await loadViewpointGraph();
  }

  // Paths 모드인데 에피소드 미로드
  if (mode === 'paths' && episodes.length === 0) {
    await loadEpisodes();
  }

  // Export 모드인데 에피소드 미로드
  if (mode === 'export' && episodes.length === 0) {
    await loadEpisodes();
  }
}

usd_snapshot.py
USD Stage → SceneSnapshot · Isaac Sim 없이도 동작 · 629 LOC

기존에는 SceneSnapshot 생성이 Isaac Sim Python 환경 내부에서만 가능했다. usd_snapshot.py는 순수 OpenUSD Python 바인딩(pxr)만으로 동일한 SceneSnapshot을 생성하는 독립 경로를 제공한다.

지원 기능

요소파싱 내용
MeshUsdGeom.Mesh → OBJ export, 변환 행렬, material 바인딩

CameraUsdGeom.Camera → fov, near/far, 변환 행렬
LightUsdLux.* → 타입별 파라미터 (intensity, color, radius 등)
InstancerUsdGeom.PointInstancer → 인스턴스 매핑 레코드
RobotStaterobomituba: namespace 커스텀 속성 → RobotState

Genesis vs. 우리 접근 (Isaac Sim + Mitsuba 3)
연구 목적 기준 비교 분석
항목 Genesis / Nyx Isaac Sim + Mitsuba 3 (우리)
RGB 합성 데이터 중간 — Nyx/Pyrender 가능하나 품질 제한 높음 — Mitsuba 3 path tracing
유리/투명체 물리 렌더링 불확실 — caustics/thin-glass 미문서 높음 — Mitsuba dielectric BSDF, 측정 BRDF 지원
NIR 렌더링 미지원 지원 — wavelength-dependent illuminant
편광 (Stokes/Mueller) 미지원 지원 — Mitsuba polarimetric variant
측정 BRDF 입력 미지원 — Disney-style 파라미터 고정 지원 — tabulated / HP-BRDF
로봇 물리 rollout 속도 높음 — MPM/rigid/fluid 통합, 10–80× 빠름(물리만) 중간 — Isaac Lab 수준
USD 파이프라인 통합 약함 — Nyx에 USD importer 없음 강함 — Isaac 네이티브 USD, robomituba_bridge
오픈소스 / 접근성 높음 — Apache 2.0, 일반 GPU 중간 — Isaac: NVIDIA 라이선스 필요
미분 가능 시뮬레이션 지원 — MPM/Tool solver, PyTorch 통합 범위 밖
판정: Genesis는 광학 관측 생성기(NIR/편광/초분광)로는 부적합하다. 그러나 로봇 상태·rollout 생성기로서는 Isaac Sim 대안 후보가 된다. "Genesis(rollout) + Mitsuba 3(광학 센서)" 연동 계층이 가능한 구조적 근거도 있다: Nyx는 카메라 센서처럼 scene에 attach되고 CUDA interop buffer로 장면 상태를 내보내므로, 동일 인터페이스를 따라 Mitsuba render-on-read 경로를 붙일 수 있다.

OpticalNav 연구 포지셔닝에 미치는 영향

✅ 독창성 추가 확인
  • Genesis는 spectral/polarimetric 렌더링 계획 자체가 없음 — 우리 NIR·편광 관측 생성기가 공백을 채움
  • Genesis의 Metal 재질은 color lookup 근사 → 유리문·반사 표면의 물리적 관측 생성 불가
  • VLN 에피소드 생성 파이프라인과 광학 위험 시나리오 (stop_before_glass / detour)는 Genesis에 없음
  • 우리 navigation_dataset 모듈 + Mitsuba 렌더 파이프라인 = 경쟁 없는 영역
