Isaac Sim이 필요한 이유
Mitsuba 단독으로는 할 수 없는 것들

Mitsuba 3는 렌더러입니다. 씬을 받아 빛을 추적하고 픽셀을 계산합니다. 로봇이 어느 위치에 있는지, 관절이 어떤 각도인지, 바퀴가 어디를 굴러가는지를 결정하지 않습니다. 그 물리 세계를 시뮬레이션하는 역할이 Isaac Sim입니다.

❌ Mitsuba 단독
  • 씬의 모든 오브젝트 위치를 사람이 직접 지정해야 함
  • 로봇이 이동하면 매 프레임마다 외부에서 transform을 수동으로 계산해서 넣어야 함
  • 물리 충돌, 중력, 관절 제약 없음 — 로봇이 벽을 통과하거나 공중에 떠도 모름
  • 관절 각도 상한/하한, 토크 제한 없음 — 물리적으로 불가능한 자세도 렌더링
  • 바퀴가 미끄러지는지, 지면과 접하는지 계산 불가
  • 센서(LiDAR, IMU) 모델링 없음 — 렌더된 이미지 외 데이터 없음
  • 실시간 피드백 루프 없음
✅ Isaac Sim + Mitsuba
  • PhysX가 매 프레임 중력·충돌·관절을 적분 → 로봇 위치 자동 결정
  • cmd_vel 입력 → 바퀴 드라이브 → 실제 이동 거리/방향 계산
  • Ackermann / Oblique / Spin 운동학이 물리 법칙 안에서 작동
  • 실시간으로 USD 스냅샷 캡처 → Mitsuba에 넘겨 고품질 렌더링
  • 로봇 관절 상태(joint_positions)를 ML 학습 데이터로 함께 저장
  • 센서 리그(RGB·NIR·Polar) 포즈가 로봇과 함께 움직임
  • Isaac timeline + ROS 연동 → 실물 로봇 제어와 동일한 인터페이스
핵심 분업: Isaac Sim = "로봇이 어디 있는가" (물리 시뮬레이션) · Mitsuba 3 = "그 위치에서 카메라에 뭐가 보이는가" (광선 추적 렌더링). 둘을 연결하는 계약이 robomituba_bridge의 SceneSnapshot입니다.

데이터 흐름으로 보는 역할 분담

①
Isaac Sim: 물리 세계 시뮬레이션
PhysX 엔진이 중력·충돌·관절 마찰을 계산. cmd_vel → 바퀴 토크 → 로봇 이동. 매 타임스텝 후 로봇 pose, 관절 각도 결정.
②
Isaac → Bridge: SceneSnapshot 캡처
stage_capture.py 가 현재 USD stage에서 메시, 재질, 카메라, 조명, 로봇 상태를 추출. SceneSnapshot + RobotState 로 패키징.
③
Bridge → Mitsuba: 렌더 요청
RenderRequest 를 render_daemon에 POST. Mitsuba는 SceneSnapshot에서 geometry, material, camera를 읽어 장면을 재구성.
④
Mitsuba: 고품질 센서 렌더링
RGB (4096 spp), Depth, Normal, Polarization 등 17개 모달리티. 물리 기반 BRDF, 편광 시뮬레이션. Isaac의 실시간 렌더러로는 불가능한 품질.
⑤
출력: ML 학습 데이터
EXR 이미지 + RobotState (joint_positions, base_pose) + ObservationBundleManifest. 물리적으로 일관된 고품질 멀티모달 데이터.

🚗
운동 모드 (RangerMiniMotionMode)
4가지 독립 운동 모드와 운동학
🚗 ACKERMANN (0)
일반 자동차형 조향. 앞 2바퀴가 같은 방향으로 꺾이고 뒤 2바퀴는 직진. linear_speed_mps + steering_angle_rad 입력.

cmd_vel 매핑: linear.x → 속도, angular.z → 조향각 (Ackermann 역기구학).
↔️ OBLIQUE (1)
게걸음(crab walk) 이동. 4바퀴 모두 같은 방향으로 꺾어서 로봇 전체가 옆으로 이동. 평행주차, 좁은 통로 횡단 이동에 유용.

입력: steering_angle_rad = ±π/2 (완전 횡이동).
🔄 SPIN (2)
제자리 회전. 4바퀴가 로봇 중심을 기준으로 탄젠트 방향으로 배치되어 로봇 중심을 축으로 회전.

입력: spin_speed_radps (양수=반시계, 음수=시계).
🅿️ PARKING (3)
주차 잠금. 4바퀴가 X자(비대칭 잠금) 방향으로 꺾여 외력에 의한 밀림 방지.

입력: park() 호출. wheel velocity = 0.

PhysX 물리 설정
중력 + 충돌 + 바닥 콜라이더 활성화

Isaac Sim에서 로봇이 공중에 떠 있는 이유: USD 씬에 물리가 꺼져 있거나 충돌 콜라이더가 없기 때문입니다. 아래 3개가 모두 있어야 중력이 작동합니다.

① PhysicsScene
중력 방향(0,0,-1)과 크기(9.81 m/s²)를 정의하는 씬 전역 오브젝트. 없으면 아무것도 떨어지지 않음. 경로: /World/PhysicsScene
② Robot Collision Prims
로봇 USD의 collision 이름 포함 prim들에 PhysicsCollisionAPI 적용. 없으면 로봇이 바닥을 통과함.
③ Ground Collider
/World/RobomitubaGroundCollider — 보이지 않는 거대한 평면 큐브. 로봇이 떨어질 바닥 역할.
④ Timeline Play
Isaac 상단 Play 버튼을 눌러야 PhysX 시뮬레이션이 시작됨. Play 전에는 설정이 있어도 물리가 돌지 않음.

Kinematic vs PhysX — 두 제어 경로
Kinematic (command_robot)
  • root xform을 직접 이동 (Δt * speed)
  • 관절 각도를 USD attr에 기록 (visual 전용)
  • 물리 엔진 불필요, 어느 모드에서나 동작
  • 충돌·중력 없음
  • 프리뷰, UI 테스트, 정적 씬 캡처에 적합
PhysX Drive (drive_ranger_mini_physx)
  • joint drive target만 기록, 이동은 PhysX가 결정
  • 중력 + 충돌 + 마찰 모두 적용
  • Timeline Play 필요
  • 물리적으로 일관된 로봇 상태
  • 실물 로봇 동작과 가장 유사한 학습 데이터 생성

# apps/isaac_extension/stage_capture.py

def capture_isaac_state(stage, *, scene_id, mitsuba_scene_ref,
                          modalities=None, illumination_setup="ambient_room",
                          assist_light=None, depth_approx=None):

    # 1. 현재 뷰포트 카메라 추출
    cam_dict = capture_active_view_camera()
    camera = CameraSpec(
        camera_to_world=cam_dict["camera_to_world"],
        fov_deg=cam_dict["fov_deg"],
        sensor_modality="multimodal",
    )

    # 2. 씬 스냅샷 (geometry + material)
    scene_snap = _extract_snapshot(stage, scene_id=scene_id, frame_id="live")

    # 3. 오브젝트별 BSDF override (유리문, 금속 등)
    objects = [IsaacObjectState(
        prim_path=mesh.source_path,
        transform=mesh.transform,
        bsdf_override=_stage_material_override(stage, mesh.source_path, scene_id=scene_id),
    ) for mesh in scene_snap.meshes]

    # 4. IsaacStateSnapshot 패키징
    snapshot = IsaacStateSnapshot(
        scene_id=scene_id,
        mitsuba_scene_ref=mitsuba_scene_ref,
        camera=camera,
        objects=objects,
        modalities=modalities or ["rgb"],
        illumination_setup=illumination_setup,
    )
    return snapshot  # → daemon_client.submit_isaac_state(snapshot) 으로 전달
핵심 설계: Isaac Sim은 카메라가 어디 있는지, 씬 오브젝트가 어떤 재질인지를 결정합니다. Mitsuba는 그 정보를 받아 그 카메라에서 보이는 빛을 물리 기반으로 계산합니다. 두 시스템이 같은 프레임·포즈를 공유하기 때문에 물리적으로 일관된 멀티모달 데이터가 나옵니다.

Codex/AGENTS.md 기록을 종합하면, 이 프로젝트의 핵심 연구 목표는 투명 장애물(유리문) 안전 평가를 위한 편광·NIR 관측입니다. Isaac Sim이 로봇 상태·시간·충돌을 결정하고, Mitsuba가 동일 프레임의 광학적 관측을 사이드카 렌더링하는 구조입니다.

🔬 연구 목표
투명 장애물(유리문, 반사면)이 있는 실내 환경에서 로봇이 안전하게 주행하려면 일반 RGB만으로는 부족합니다. NIR, 편광(DOP/AoLP)은 유리면을 다르게 보이게 해서 hazard detection을 가능하게 합니다.

실물 실험 전에 시뮬레이션에서 충분한 데이터를 만들어 모델을 먼저 학습하는 것이 목표입니다.
🏗️ 아키텍처 철학
Isaac Sim을 "렌더 엔진"으로 쓰지 않습니다. Isaac은 씬의 진실의 원천(source of truth) — geometry, robot state, collision, time을 담당하고, Mitsuba는 그것을 광학적으로 재현합니다.

둘 사이를 연결하는 계약이 robomituba_bridge입니다.
📦 Sidecar Renderer
Isaac Sim의 뷰포트를 대체하지 않습니다. Isaac이 한 프레임을 결정하면, 같은 프레임에 대해 Mitsuba가 오프라인 배치로 고품질 렌더를 생산합니다.

→ 실시간 시뮬레이션 + 오프라인 고품질 렌더 데이터를 병행합니다.
🗺️ 장기 방향: VLN/Navigation
단일 프레임 observation → 시퀀스 기반 episode로 확장이 다음 단계입니다. 로봇이 경로를 따라 이동하며 각 timestep마다 멀티모달 관측을 저장하는 VLN(Vision-Language Navigation) 학습 데이터를 생성하는 플랫폼이 목표입니다.

Waypoint Models for Instruction-guided Navigation in Continuous Environments
Krantz, Gokaslan, Batra, Lee, Maksymets — Georgia Tech / Facebook AI
