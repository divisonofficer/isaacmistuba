OpticalNav 맥락에서의 재질 분류

재질 유형예시필요 모델Mitsuba 플러그인비고
일반 사무실 물체 책상·의자·벽·바닥·플라스틱·금속·천 BRDF 로 충분 diffuse, roughconductor, principled 불투명 — 반사만 모델링
유리문 / 투명 파티션 유리문, 반투명 칸막이 BSDF 필수 dielectric, roughdielectric, thindielectric 반사 + 투과 + 굴절 동시 발생
편광 측정 재질 (hpBRDF) measured BSDF 데이터 (MERL, UTIA 등) BRDF (반사 측정) measured, 커스텀 .pbrdf 측정 데이터가 반사만 포함하면 BRDF. 유리 등 투과 재질은 polarized BSDF / Mueller BSDF로 확장 필요.
편광 유리 / NIR 투과 편광 유리문, NIR 반투과 소재 polarized BSDF Mueller matrix BSDF (커스텀 구현) 편광 상태 변화까지 추적 — stokes vector 기반. OpticalNav 장기 목표.
한 줄 정리: 불투명 사무실 물체는 BRDF로 충분하지만, 유리문은 반사와 투과가 동시에 발생하므로 BSDF(= BRDF + BTDF)가 필요하다. 편광·NIR 효과까지 포함하면 Mueller BSDF로 확장해야 한다. 우리가 "measured BRDF를 쓴다"고 말할 때는 불투명 재질의 반사 응답을 가리키는 것이다.

공유오피스 chair/material test에서 hpBRDF channel-split 재질을 RGB로 보이게 하기 위해 614nm, 542nm, 446nm 세 pass를 렌더한 뒤 R/G/B로 합성했다. 이 경로는 기존 Mitsuba RGB 렌더와 메모리 모델이 다르다.

기존 RGB
1 scene
RGB-valued BSDF/texture를 한 scene에서 계산한다. scene/BVH/OptiX/texture cache가 한 벌이다.
현재 hpBRDF RGB

왜 기존 RGB와 다른가

항목기존 Mitsuba RGBhpBRDF channel-split RGB
채널 의미 renderer 내부 RGB vector channel. 단일 파장 measured BSDF scene을 외부 orchestration으로 3회 렌더.
Scene resource scene object, geometry, BVH, OptiX accel, texture, BSDF가 한 벌. scene_614, scene_542, scene_446이 서로 다른 XML이라 cache가 세 벌을 잡을 수 있다.
spp 영향 주로 시간과 일부 integrator/sampler buffer에 영향. 마찬가지로 시간 영향이 크다. VRAM 주범은 spp보다 measured BRDF와 scene 중복이다.
속도/안정성 tradeoff resident scene cache가 안정적으로 이득. 단일 GPU에서는 cache 유지보다 band 사이 scene release가 안정성에 더 중요할 수 있다.

운영 전략

용도권장 전략이유
Hot preview 기본은 low spp + single-band 또는 material proxy RGB. 3-band measured RGB는 옵션으로 둔다. preview는 구도/방향 확인이 목적이므로 4096 spp × 3 pass는 과하다.
단일 GPU final R → cache release → G → cache release → B → 합성. resident cache 이득보다 OOM 방지가 우선이다.
멀티 GPU final GPU0=614nm, GPU1=542nm, GPU2=446nm band sharding. 각 GPU에는 scene 한 벌만 올라가므로 메모리 중복이 GPU별로 분산된다.
장기 구조 measured_polarized_rgb 또는 measured_polarized_channels custom BSDF plugin. BSDF 내부에서 3개 pBRDF file을 읽고 한 scene에서 RGB/Spectrum 값을 반환하면 scene/BVH/OptiX 중복을 줄일 수 있다.
결론: hpBRDF RGB 3채널 합성은 불가능한 문제가 아니라 현재 구현이 외부 3-pass라서 VRAM 중복이 생기는 문제다. 단기적으로는 preview와 final 정책을 분리하고, 단일 GPU에서는 wavelength pass 사이 cache를 비워야 한다. 장기적으로는 channel-split .pbrdf 세 개를 묶는 Mitsuba BSDF plugin이 가장 적절하다.

Instruction 생성 파이프라인 — 3단계

1·2단계는 결정론적(재현 가능), 3단계는 offline 배치로 렌더링과 분리. LLM은 문장화 마지막 단계에만 사용하고, 사실 정보는 simulator metadata에서 가져와 hallucination을 방지.

1. Symbolic Route Summary — 결정론적 그래프 경로에서 5가지 이벤트를 추출한다: Start Context (시작 지점 주변 랜드마크), Route Events (move_forward / turn / landmark_pass), Goal (목표 지역 설명), Hazards (유리·반사 면 회피 플래그), Stop Condition (종단에서 정지 기준).
2. Template Instruction — 결정론적 Route Summary → template 선택 → string 합성. Hazard 플래그가 있으면 hazard_aware template 선택, 없으면 landmark 또는 concise. 출력이 instruction.primary (재현 가능).
3. LLM Variants — offline 배치 instruction.primary + Route Summary JSON → LLM (GPT-4o-mini / Claude Haiku, temp 0.9) → N개 변형. 새 landmark 창작 금지, grounding 검증기 통과 후 instruction.variants 저장. 예산: 1만 episode ≈ $2–4.

관련 연구 — VLN Instruction Generation

"path-to-instruction generation", "speaker-based VLN augmentation", "LLM/LMM-assisted navigation instruction generation" 키워드 축을 중심으로 조사. OpticalNav의 포지셔닝: 일반 VLN benchmark를 대체하는 것이 아니라, 투명·반사 장애물 환경에서 경로·언어·다중 모달 관측이 함께 정렬된 synthetic fine-tuning episode 생성.

ScaleVLN 심층 분석 — OpticalNav 설계 관련 인사이트

ScaleVLN 논문 질의응답으로 확인한 내용. OpticalNav 데이터 파이프라인 설계에 직접 참조.

1. Vision-Path 매핑 방식: Vertex-only 이산 파노라마 시퀀스

ScaleVLN의 경로 데이터에서 시각 정보는 경로에 포함된 vertex 개수만큼만 제공된다. edge(두 노드 사이 이동 구간) 위에서의 연속적 이미지는 포함되지 않는다. 각 vertex에서 수평 12방향 × 수직 3고도 = 36장 파노라마를 관측값으로 제공.

표현내용
경로 길이 5 hop5개 vertex × 36장 파노라마 = 180장의 feature sequence
edge 위시각 정보 없음 — 순간이동(teleport) 처리
저장 형태PNG → ViT/CLIP 인코딩 → feature vector (.hdf5 / .lmdb)
이유: 실제 Matterport3D 스캔은 수 미터 간격 이산 촬영이라 edge 위 이미지가 존재하지 않음. 학습 효율: 에이전트의 의사결정 포인트(어느 방향으로 갈까?)는 vertex에서만 발생하므로 vertex 시각 정보만으로 충분.
연속 환경(R2R-CE)에서는?
vertex-only 데이터로 학습한 모델이 Candidate Waypoint Predictor를 통해 edge 위를 0.25m씩 이동하는 연속 환경에서도 잘 작동함을 논문이 입증. "이산 학습 → 연속 실행"의 일반화 능력 확인.
OpticalNav 시사점
Mitsuba 렌더는 노드(viewpoint)마다 실행 → 자연스럽게 vertex-only 방식과 일치. Isaac Sim은 합성 씬이므로 edge 위 연속 render도 가능하지만, ScaleVLN 실험 결과를 보면 초기 데이터셋은 vertex 단위로만 생성해도 무방. 연속 환경 학습은 2차 확장으로.

2. 데이터 파이프라인 — 생성 → 학습 → 실행 단계 구분

① 데이터 생성 (Offline) HM3D / Gibson 3D 스캔 → Habitat-Sim 원시 렌더링 → Co-Mod GAN으로 왜곡·누락 영역 복원 → 포토리얼리스틱 PNG 저장. 한 번만 수행. 이후 재실행 불필요.
② Feature 추출 (Offline) 복원된 PNG를 CLIP / ViT로 인코딩 → feature vector 시퀀스를 .hdf5 / .lmdb에 저장. 학습 시 PNG를 직접 읽지 않고 feature DB를 조회 → 속도 최적화.
③ 모델 학습 (Offline) feature 시퀀스 + instruction → seq2seq 학습. 4.9M 쌍을 batch로 처리. 시뮬레이터 불필요 — 순수 supervised learning.
④ 검증·실행 (Online) Habitat-Sim이 3D 메쉬(.glb/.obj)를 실시간 렌더링. 에이전트의 action → 시뮬레이터가 새 좌표 계산 → RGB + Depth + 센서 데이터 반환. R2R-CE 평가는 이 단계에서 수행.

3. Instruction 생성 방식 — EnvDrop Speaker (LSTM seq2seq)

4.9M 경로에 대해 수작업 annotation 없이 EnvDrop Speaker 모델이 자동 생성. 작동 방식: 경로상 각 vertex의 파노라마 feature를 순서대로 입력 → LSTM decoder가 R2R 스타일 자연어 문장 출력.

비교 모델생성 품질에이전트 성능
GPT-2문장 다양성↑, 유창성↑낮음 — 경로 정렬 약함
EnvDrop Speaker (LSTM)단순하지만 핵심 landmark 명시높음 — navigation cue 정확
교훈: 문장의 유창함보다 경로-언어 정렬(alignment)이 VLN 학습에 더 중요. LLM paraphrase를 쓸 때도 원본 경로 사실(방향, landmark, stop condition)은 반드시 고정해야 하는 이유.
Seq2Seq 생성 과정 예시
vertex 1: 거실 (소파·TV feature) →
vertex 2: 복도 (액자 feature) →
vertex 3: 주방 (식탁·냉장고 feature)
"Exit the living room past the sofa, walk down the hallway, enter the kitchen and stop by the table."
OpticalNav 적용 방향: 초기에는 symbolic route summary → template instruction (결정론적) 방식으로 시작. LSTM speaker 대신 우리는 simulator metadata(landmark, turn angle, hazard flag)를 직접 활용하므로 GPT-2 hallucination 문제를 구조적으로 우회 가능.

GSA-R2R (ICLR 2025) 심층 분석 — 3단계 Instruction 오케스트레이션

ScaleVLN이 "얼마나 많이"를 해결했다면, GSA-R2R은 "얼마나 정확하고 다양하게"를 해결한다. 핵심 기여는 두 가지: ①Speaker→VLM→LLM 3단계 instruction 파이프라인, ②에피소드 간 환경 적응(GR-DUET).

1. 기존 방식 대비 발전 지점

구분기존 VLN (ScaleVLN 등)GSA-R2R 제안
Instruction 품질 Speaker(LSTM) 단일 생성 — 방향 오류, 모호한 landmark 포함 VLM이 경로 이미지와 대조해 오류 수정 → 정확도 보장
Instruction 다양성 R2R 스타일 균일한 어투 LLM role-playing으로 사용자·장소별 개성 있는 어투 생성
환경 범위 주거 공간(Matterport3D) 위주 HM3D 기반 + 영화관·실험실·상점 등 non-residential OOD 포함
에피소드 간 기억 매 에피소드 지도 리셋 GR-DUET: Global Topological Graph 유지 → 경험 누적 성능 향상

2. 3단계 Instruction 파이프라인

Stage 1 — Speaker (초안) EnvDrop Speaker(LSTM)가 경로 feature sequence를 입력받아 자연어 지시문 초안 생성. 빠르고 저렴하나 방향 오류·landmark hallucination 포함 가능.
출력: 날것의 R2R 스타일 문장
Stage 2 — VLM (검수·수정) 내비게이터 모델이 Stage 1 지시문으로 주행 시도. 실패한 경우에만 GPT-4o가 경로 파노라마 + top-down 뷰를 보고 오류를 CoT로 탐지·수정. 성공한 지시문은 그대로 통과 — 비용 최적화.
출력: 정확도 보장된 Basic instruction
Stage 3 — LLM (스타일 부여) Basic instruction을 기반으로 LLM이 persona/context 변환. 사실 정보(방향·landmark·stop condition)는 고정, 어투만 변형. 건물 유형에 따라 분기:
  • Residential → User Style만
  • Non-residential → User Style + Scene Style 둘 다
출력: 다양성 확보된 OOD-robust instruction

3. VLM 실패-조건부 적용 — 왜 실패한 경우만?

성공한 지시문 = 내비게이터가 실제로 목적지에 도착 → 이미 "기계가 이해하기 충분히 정확"하다는 검증 완료. VLM으로 재처리할 이유 없음.
실패한 지시문 = Speaker가 방향 역전·landmark 오류 등을 낸 신호. 이때만 GPT-4o 투입 → 경로 이미지와 대조하여 어디가 틀렸는지 탐지 후 수정. 결과: 품질 상향 평준화 + API 비용 최소화.

4. Residential vs Non-residential — Stage 3 분기 이유

구분ResidentialNon-residential

OpticalNav 포지셔닝 — Related Work 논문 표현

Prior VLN datasets (R2R, RxR) establish high-quality human-written navigation instructions, but annotation cost limits targeted coverage of rare optical hazards such as glass doors, mirrors, and transparent partitions. Speaker-based augmentation methods (Speaker-Follower, EnvDrop) and large-scale synthetic pipelines (ScaleVLN) generate instruction-trajectory pairs at scale, while recent work (MARKY-MT5, InstruGen, BEVInstructor) improves grounding through landmarks, BEV geometry, and LMM verification. In contrast, our goal is not to replace general VLN benchmarks, but to generate optically grounded synthetic fine-tuning episodes where language instructions, robot trajectories, and multi-modal observations (RGB, Depth, NIR-like, Semantic) are jointly aligned around transparent and reflective navigation hazards.

OpticalNav instruction variant 설계 — 5-style scheme

Style예시학습 목적
goal_only"Go to the row of open desks and stop beside the nearest desk."기본 goal-reaching 능력
landmark_path"Move forward through the shared office, turn slightly right near the desk row, and stop beside the open desk area."intermediate waypoint 활용 능력
hazard_aware"Go to the open desk area using the clear walkway. Do not cross the glass partition."언어 지시 기반 hazard 회피
stop_before_glass"Move toward the desk visible beyond the glass partition, but stop before the glass wall."visual ambiguity + language cue 조합
ambiguous"Go to the desk area ahead."낮은 품질 instruction에서의 실패 분석 (baseline 비교용)
실험 설계: 동일 장면·경로에서 (RGB-only + ambiguous) → (RGB-only + hazard-aware) → (RGB+NIR+hazard-aware) 순으로 비교하면 언어·관측·안전 행동이 묶인 데이터의 효과를 분리 측정 가능.
