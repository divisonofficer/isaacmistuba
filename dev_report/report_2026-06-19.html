Infinigen indoor → Mitsuba 렌더 가능 상태로 import

Infinigen 이 만든 절차적(procedural) 실내 .blend 씬을 OpticalNav 의 authoring map 으로 옮겨, Mitsuba 3 (OptiX7) 가 그대로 렌더 가능한 상태로 만드는 2-stage 컨버터의 설계와 구현 정리.

핵심 격차는 "Blender 의 절차적 shader graph" 와 "Mitsuba 의 평탄(flat) PBR/측정 BSDF" 사이에 있다. 우리는 (a) Cycles 가 절차 셰이더를 albedo 로 bake 해서 평탄화하고, (b) 이름 키워드 기반 optical class 분류로 mirror / glass / metal 을 분석적/측정 BSDF 로 강제 라우팅하는 두 가지 단순화로 이 격차를 메운다.

결론. Infinigen 은 "방 모양 + 가구 배치 + 절차적 PBR + 라이팅" 까지 다 차려준다. 우리가 하는 일은 그것을 Mitsuba 가 직접 이해 가능한 평탄 표현으로 평탄화 (bake) 하고, 그러면서도 측정 pBRDF 가 가져갈 mirror/metal/glass 슬롯은 보존하는 것이다.

왜 Infinigen 인가

OpticalNav 데이터셋은 실내 viewpoint × heading 스윕에서 RGB / depth / polarization 등 멀티모달 관측을 필요로 한다. 즉 씬 수 × 카메라 × heading × modality 가 모두 곱해진 큰 데이터셋이 필요. 직접 모델링하기엔 손이 너무 많이 가고, 기존 CC0 데이터셋(Cornell, Office Lobby 등)은 수도 적고 의미도 단조롭다.

Infinigen 은 (a) 절차적이라 무한히 다양한 씬을 만들고, (b) 방 / 가구 / 조명 / 문·창문 같이 의미가 있는 단위로 organize 되어 있어 traversability·hazard·instruction grounding 같은 OpticalNav 메타데이터를 추출하기 좋다.

한 마디로 — "수량 × 다양성 × 의미 라벨" 셋을 한꺼번에 주는 generator 다. 단점은 Blender / 절차 셰이더 / 거대한 polygon 수.

Infinigen 에셋이 실제로 제공하는 것

1) 지오메트리 (Geometry)

  • scene.blend(또는 손상 시 scene.blend1 백업) 한 파일 안에 모든 mesh.
  • 좌표계는 Z-up (Blender 관행). Mitsuba/OpticalNav 의 authoring world 는 Y-up.
  • 각 object 는 Blender collection 으로 묶임: dining-room_0/0 같은 room key + factory(ChairFactory, TableDiningFactory, WardrobeFactory, ...) 명명.
  • 구조물(structure)은 객체명 suffix 로 표시: .wall, .floor, .ceiling, .exterior.
  • Polygon 수는 객체당 수만~수십만 → preview 용 decimation 필요.

2) 재질 (Material) — PBR shader graph

각 object 의 material slot 마다 Blender Principled BSDF 노드(또는 procedural shader 묶음) 가 달려 있다. 우리가 추출 가능한 채널:

PBR 채널Infinigen 에서 어떻게 주어지나우리 처리
base_color (3채널)Principled BSDF의 Base Color 소켓 — 단색이거나 노드 트리(Noise·Voronoi·MixRGB 등)에서 도착단색이면 그대로, 절차이면 Cycles DIFFUSE bake → PNG atlas
metallic (0–1)Principled BSDF의 Metallic 소켓 (값 또는 노드)그대로 읽되 신뢰성 낮음 — name keyword 가 우선
roughness (0–1)Roughness 소켓그대로 읽음. 기본값 0.6 이 많아 frosted 판정엔 안 씀
iorIOR 소켓diffuse/glass 모두에 보존 (단 현재 binding 은 strategy 고정값 사용)
alphaAlpha 소켓1.0 미만이면 투명 가능성 표시 (glass 분류 보조)
emission (strength + color)Emission Strength / Color 소켓area emitter 의도 신호로 사용
이미지 텍스처Image Texture 노드의 file path (드물지만 있음)image_textures[] 로 보존, 재질 binding 에서 base_color_texture_ref 로 사용 가능

3) 조명 (Lights)

  • Blender LIGHT object: type=POINT / AREA / SUN / SPOT, plus color · energy · position.
  • AREA 라이트는 추가로 size / size_y (직사각형 크기).
  • SUN 라이트는 행렬에서 forward 벡터를 뽑아 direction 으로 변환.

4) 의미 정보 (Semantic)

  • Factory name 이 가장 강한 신호. ChairFactory → chair, TableDiningFactory → table, WardrobeFactory → shelf, 등 키워드 기반 매핑.
  • 구조물 분류는 객체 이름 suffix(.wall/.floor/.ceiling/.exterior) 가 결정한다.
  • room key (예 dining-room_0/0) 는 다중 방 씬에서 어떤 방에 속하는지를 결정.
  • 유리 / 거울 / 금속은 material 이름의 키워드(glass, mirror, brushed_metal, gold, ...) 가 가장 신뢰 가능.

Infinigen ↔ Mitsuba 격차

1. 좌표계
Blender Z-up ↔ Mitsuba/OpticalNav Y-up. OBJ exporter 의 forward=-Z up=Y 옵션 + authoring 2D 좌표(authoring_y = -blender_y)로 통일.
2. 절차적 shader
Mitsuba 는 Blender 의 noise/voronoi/mixRGB 같은 노드 그래프를 모름 → Cycles DIFFUSE bake 로 단일 albedo PNG 로 평탄화.
3. 광학적 분류
Infinigen 의 metallic=0.0 이 실제로는 brushed metal 이기도 함(쉐이더 이름 vs 값 불일치). name keyword 가 우선, metallic 은 약한 fallback.
4. 측정 pBRDF 슬롯
금속/거울/유리는 baked albedo 대신 measured_polarized / conductor / dielectric 같은 분석/측정 BSDF 로 라우팅해야 분광·편광 응답이 살아 있음.
5. 다중 방
Infinigen 은 한 씬에 여러 방 shell 을 빈 채로 쌓아둠. 가구 있는 방만 "finished" 로 간주해 선택.
6. blend 파일 손상
scene.blend 의 header 가 깨진 경우가 흔함. scene.blend1 백업이 valid → magic bytes BLENDER[-_] 검사로 자동 fallback.

Stage 1 — Blender 안에서 export

tools/infinigen/blender_export_scene.py · bpy 모듈로 실행 · 출력: scene_manifest.json + meshes/ + textures/

Stage 1 — Blender 안에서 export

Infinigen 의 bundled Blender 바이너리는 libs 문제로 종종 깨져 있어, Conda infinigen 환경의 bpy 모듈을 import 해 헤드리스로 실행한다.

입력

하나의 .blend 또는 .blend1 (header magic 검증 후 자동 선택).

핵심 동작

for obj in bpy.data.objects (MESH only): semantic_type ← factory_name keyword (chair / table / shelf / plant / ...) kind ← structure(.wall/.floor/.ceiling/.exterior) / window / door / furniture optical_class ← name keyword (glass / mirror / metal_gold / metal_steel / metal_aluminum / diffuse) ↑ metallic 값은 fallback 일 뿐 world_bbox ← obj.bound_box → world space (Z-up) # 좌표/배치 정규화 — render 시 OBJ 를 authoring center 로 옮겨 적용 가능하게 offset ← centre xy + bottom z 를 0 으로 이동 obj.matrix_world ← Translation(offset) · 원본 matrix_world export OBJ (Y-up, forward=-Z) → meshes/{oid}.obj export GLB (PBR/UV 보존) → meshes/{oid}.glb if procedural shader and not skipped: Cycles bake DIFFUSE color → albedo PNG → meshes/{oid}.mtl 에 map_Kd 패치 # mirror/glass 는 baked albedo 를 버린다 (분석 BSDF 가 알아서 처리) if optical_class in (mirror, glass): meshes/{oid}.mtl 에서 Kd / map_Kd / Ks / bump 모두 제거 obj.matrix_world ← 원래대로 복원 for light in bpy.data.objects (LIGHT only): type / color / energy / world_pos / authoring_xy=(x, -y) / base_height=z AREA: size, size_y SUN: forward 벡터로부터 direction # scene_manifest.json 작성 { "units": [ {id, kind, semantic_type, factory, world_bbox_min/max, dimensions, yaw_deg, place_center, place_size_m, place_base_height_m, polys, materials, optical_class, mesh_obj, mesh_glb, baked_albedo}, ... ], "materials": { "name": { base_color, metallic, roughness, ior, alpha, emission_strength, emission_color, optical_class, image_textures, procedural, is_glass, is_emissive } }, "lights": [ {name, type, color, energy, world_pos, ...} ], "cameras": [ ... ] }

핵심 결정들

  • OBJ + MTL 이 Mitsuba 의 입력: 평탄한 albedo / Kd 만 쓰는 단순 포맷이라 BSDF 라우팅을 우리 쪽이 통제하기 쉽다.
  • GLB 는 에디터 preview: PBR/UV 가 보존되어 future quality upgrade 용. 지금 렌더 경로는 사용 안 함.
  • Cycles DIFFUSE bake (use_pass_direct=False, use_pass_indirect=False, use_pass_color=True): 절차 텍스처의 "색"만 빼와서 lighting 의존성 없는 albedo atlas 를 만든다.
  • 120k 폴리곤 초과 mesh 는 bake 스킵: bake 비용이 가파르게 올라가서, decimation 우선순위가 더 높다.
  • Origin-local 좌표: 렌더 시 authoring center 만큼 translate 하므로, OBJ 는 자체 원점에 centre/bottom 이 와야 한다 (bbox 가로 중심 x=z=0, 바닥 y=0).
  • fd 1/2 silence: Blender 가 콘솔에 쏟아내는 Synchronizing object… / Writing to… 등 C-level 스팸을 /dev/null 로 보내 tqdm bar 가 깨지지 않게.

Stage 2 — OpticalNav 으로 import

Stage 1 의 scene_manifest.json 을 읽어 OpticalNav 의 authoring map + traversability grid + 측정 pBRDF binding 까지 생성한다. 결과를 install_shared_office_sample 흐름에 그대로 태우면 webui 가 인식하고 데몬이 바로 렌더 가능.

핵심: _material_binding

optical_class 가 render binding 의 strategy 를 결정한다:

optical_classbsdf_strategybaked albedocapabilities
glass (frosted 키워드 있으면 roughdielectric)dielectric / roughdielectric버림RGB
mirrorconductor (Al)버림RGB
metal_goldmeasured_polarized (fake_gold)albedo_scale 로 변조RGB + polarization
metal_steelmeasured_polarized (suj2)albedo_scale 로 변조RGB + polarization
metal_aluminummeasured_polarized (aluminum)albedo_scale 로 변조RGB + polarization
diffuse (그 외)roughplasticmap_Kd 로 그대로RGB
측정 BSDF × baked albedo modulation. 6-17 보고서의 "svBRDF Option 1" — 측정 pBRDF 가 각도/편광 응답을 담당하고, baked albedo 가 공간 색상 변조를 담당. 측정 RGB plugin (measured_polarized_rgb) 이 프로덕션 빌드에 있어야 컬러가 살아남고, 없으면 grayscale fallback. 이 한계는 두 빌드 (build/mitsuba3-optix7 vs 표준) 문제로 6-15 보고서에 정리됨.

nav flags · 방 선택 · traversability

  • nav flags: furniture → blocks_navigation=true; door → glass_door hazard; window → transparent_obstacle hazard. instruction/goal candidate 도 semantic_type 으로 자동.
  • 방 선택: 모든 floor footprint 를 모은 뒤 가구 ≥1 개가 footprint 안에 있는 방만 finished 로 채택. 빈 shell 방은 버림.
  • traversability grid: 채택된 floor footprint 의 union 을 navigable region 으로 삼고, furniture AABB 로 carve. 구조물(.wall/.floor/...)과 window 는 carve 안 함 (벽이 방 전체 footprint 와 겹치므로).
  • face-less OBJ skip: 잘못 export 된 Bézier curve 같은 face 없는 OBJ 는 Mitsuba 로더가 죽이므로 import 시 사전 skip.

통합 launcher — 한 스크립트로 일발

Stage 1 은 infinigen conda env (bpy), Stage 2 는 robomituba env (mitsuba_converter / navigation_dataset). 두 env 를 동시에 활성화 못하므로 apps/run_infinigen_import.sh 가 양쪽을 순차 실행한다.

bash apps/run_infinigen_import.sh data/.../singleroom_furnished ↓ pick_blend() — scene.blend 손상 시 scene.blend1 로 자동 fallback $INFINIGEN_PYTHON tools/infinigen/_run_bpy.py <blend> blender_export_scene.py -- \ --out out/infinigen_imports/<name> [--bake] ↓ scene_manifest.json + meshes/ + textures/ $PYTHON apps/import_infinigen_scene.py \ --manifest out/infinigen_imports/<name>/scene_manifest.json \ --scene-id infinigen_<name> --force [--room KEY] ↓ out/opticalnav/opticalnav-v0.2/scenes/<scene-id>/ ├ authoring_map.json ├ scene_annotation.json ├ traversable_grid.npy ├ render_scene.xml (Mitsuba 입력) └ ... → webui 가 자동 인식, render daemon 이 바로 렌더 가능

주요 옵션

  • --no-bake: bake 스킵. 빠르지만 절차 색은 grayscale 비슷.
  • --skip-export: 이미 Stage 1 결과가 있으면 Stage 2 만 다시 실행.
  • --room KEY: 특정 방만 (예 dining-room_0/0) 유지.
  • --keep-empty-rooms: 가구 없는 방도 포함.
  • --no-normalize-origin: Infinigen 의 raw world coord 보존 (원점 정렬 안 함).
