Spatially Varying BRDF 개선 계획

기존 RGB asset이 이미 가진 albedo / normal / metallic / roughness texture를 버리지 않고, 측정 pBRDF 기반 광학 렌더와 어떻게 결합할지에 대한 구현 가능성 검토.

단기 결론: object-level 측정 pBRDF에 기존 albedo texture를 곱하는 hybrid 방식을 먼저 구현하고, part 분리는 고가치 asset 보정용으로 병행한다. per-pixel pBRDF linking은 연구 트랙으로 분리한다.

오늘의 결론

1순위
1안
단일 pBRDF × albedo texture. 지금 코드와 가장 가깝고 OpticalNav 품질 개선 효과가 즉시 크다.
보조 전략
2안
물체가 실제로 여러 재질이면 part/slot 단위 분리가 맞다. 자동화보다 asset cleanup 성격이 강하다.
연구 트랙
3안
PBR map을 분석해 texel별 pBRDF id를 그리는 방식. 가능하지만 플러그인, 메모리, 물리 정합성 부담이 크다.
선행 조건
RGB
measured_polarized_rgb가 프로덕션 OptiX7 빌드에서 로드되는 상태가 먼저 필요하다.
권장 방향: "완전한 SV-BRDF"를 바로 목표로 잡지 않는다. 우선은 측정 pBRDF가 각도별/편광별 응답을 담당하고, 기존 texture가 공간 색상 변화를 담당하는 hybrid 근사를 만든다. 논문/데이터셋 설명에서도 이것을 "measured optical response with texture-preserved spatial modulation"으로 명시하는 편이 방어 가능하다.

문제 재정의

6월 15일 보고서에서는 Infinigen/RGB 기반 asset을 Mitsuba + 측정 pBRDF에 연결할 때, 단일 pBRDF를 물체 전체에 적용하면 나무결, 패브릭 직조, 마블 패턴, 페인트 얼룩 같은 공간 변화가 사라진다고 정리했다. 오늘의 질문은 "SV-BRDF를 완성하자"보다 구체적이다. 이미 asset에 존재하는 PBR texture 정보를 어느 수준까지 재사용할 것인가다.

기존 asset ├─ geometry / UV ├─ albedo 또는 base_color texture ├─ normal map ├─ roughness map └─ metallic map │ ▼ 측정 pBRDF replacement ├─ 각도별 반사 응답 ├─ 분광 / 편광 응답 └─ RGB channel-split 응답 │ ▼ 핵심 질문 "texture는 공간 패턴으로 보존하고, pBRDF는 광학 응답으로 보존할 수 있는가?"
용어 구분: 여기서 1안은 엄밀한 의미의 SV-BRDF가 아니라 texture-modulated measured BRDF다. 3안처럼 위치마다 pBRDF 자체가 바뀌어야 엄밀한 SV-BRDF에 가깝다.

현재 코드 기반에서 가능한 것

구성 요소현재 상태의미
MaterialRecord.textures base_color, albedo, diffuse, roughness 같은 texture slot을 담을 수 있다. 새로운 scene schema 없이 texture 정보를 계속 전달할 수 있다.
mitsuba_builder._material_to_bsdf 일반 principled 경로에서는 base color / roughness texture를 Mitsuba bitmap texture로 내보낸다. RGB asset의 texture 보존 경로는 이미 있다.
multimodal.py staging diffuse override / polarized fallback scene을 만들 때 기존 BSDF의 base texture를 찾아 새 BSDF에 복사한다. XML 재작성 단계에서 texture를 보존하는 패턴이 이미 존재한다.
measured_polarized_rgb 현재 표준 트리 구현은 filename_r/g/b와 alpha_sample 중심이다. albedo/roughness/normal texture 입력은 없다. 1안을 제대로 하려면 플러그인 또는 XML 조합 레벨에서 texture multiplier를 추가해야 한다.
프로덕션 빌드 build/mitsuba3-optix7에 플러그인이 컴파일되어 로드되는지 확인이 선행되어야 한다. 이 문제가 남으면 어떤 texture 결합안도 실제 dataset 렌더에 반영되지 않는다.

세 가지 제안 검토

각 안은 서로 배타적이라기보다 단계가 다르다. 1안은 즉시 품질 개선, 2안은 asset 구조 보정, 3안은 장기 연구 구현이다.

1안 — 오브젝트 하나에 단일 pBRDF를 샘플링한 뒤 기존 texture를 곱한다

구현 난이도
낮음-중간
현재 XML/texture 보존 경로를 재사용할 수 있다. 플러그인 입력만 늘리면 된다.
물리 정합성
근사
색상 texture가 BRDF amplitude를 modulate한다고 보는 모델. 정확한 측정 SV-BRDF는 아니다.
데이터셋 효과
큼
흑백/단색화 문제를 줄이고, 기존 asset의 시각적 다양성을 바로 살릴 수 있다.

구현 방식

  • measured_polarized_rgb에 optional texture child를 추가한다. 예: <texture name="albedo_scale" type="bitmap">.
  • eval()에서 pBRDF RGB/Spectrum intensity를 계산한 뒤, albedo_scale->eval(si) 값을 곱한다.
  • 기존 BSDF에 있던 base_color / diffuse_reflectance texture를 measured replacement 단계에서 albedo_scale으로 옮긴다.
  • normal map은 Mitsuba의 bumpmap wrapper 또는 별도 normal perturbation 경로로 나중에 붙인다. 1차 구현에서는 albedo만 먼저 처리한다.
  • roughness/metallic map은 바로 곱하지 않는다. 측정 pBRDF 안에 이미 lobe shape와 도체/유전체 성격이 들어있기 때문에, 무작정 scalar로 변형하면 해석이 흐려진다.
판정: 구현 가능. 6월 17일 기준 가장 현실적인 MVP다. "텍스처 공간 변화는 보존, pBRDF 각도/편광 응답은 대표 재질에서 제공"이라는 가정도 명확하게 설명할 수 있다.

주의점

항목주의할 점대응
에너지 보존 밝은 albedo texture를 그대로 곱하면 measured reflectance가 과도하게 커질 수 있다. texture를 평균 1.0 또는 대표 pBRDF 색상 기준으로 normalize하고 clamp 정책을 둔다.
색상 의미 texture 색상이 pigment인지 조명 bake인지 알 수 없다. asset import 단계에서 baked-lighting 의심 texture를 audit한다. 초기에는 실내 asset의 base_color만 사용한다.
편광 해석 texture는 편광을 바꾸지 않고 intensity만 바꾸는 가정이다. 보고서/논문에서는 "polarization-preserving amplitude modulation"으로 제한을 명시한다.

2안 — 오브젝트를 여러 파츠로 분리해서 pBRDF를 다르게 적용한다

구현 난이도
중간
material slot 기준이면 쉽다. texture segmentation으로 자동 분리하면 난이도가 올라간다.
물리 정합성
좋음
실제로 다른 재질인 영역에 다른 pBRDF를 붙이는 것은 해석이 자연스럽다.
데이터셋 효과
선택적
chair frame/seat, desk metal leg/wood top처럼 복합 오브젝트에서 효과가 크다.

구현 방식

  • 이미 USD/OBJ가 material slot 또는 mesh part를 분리하고 있으면, 각 slot을 독립 material로 보고 pBRDF를 다르게 매핑한다.
  • 분리되어 있지 않은 단일 mesh는 자동 분리보다 authoring/export 단계에서 part를 유지하는 것이 우선이다.
  • texture 기반 자동 분리는 color cluster, metallic/roughness threshold, UV island 단위로 triangle group을 나누는 방식이 가능하다.
  • 각 part에는 1안의 pBRDF × albedo texture를 다시 적용할 수 있다.
판정: 구현 가능하지만 1안의 대체재라기보다 보조 전략이다. "하나의 물체가 여러 실제 재질로 구성된 경우"에만 정당화된다. 모든 texture pattern을 part로 쪼개려 하면 geometry 수, draw/shape 수, BVH 비용, UV seam 문제가 커진다.

적용하기 좋은 예

오브젝트분리 단위매핑 예
의자metal frame / fabric seat / plastic wheelaluminum / rough fabric 근사 / black rough plastic
책상wood top / metal leg / plastic cable coverwood는 analytic+texture 또는 대표 plastic, leg는 aluminum
파티션glass panel / aluminum frame / rubber gasketdielectric glass / aluminum / black rough plastic
바닥tile / grout / carpet striprough ceramic / diffuse grout / fabric 근사

3안 — PBR texture map을 분석해서 각 픽셀에 최적 pBRDF를 링킹하는 pBR map을 그린다

구현 난이도
높음
per-texel pBRDF id map, multi-pBRDF plugin, memory policy, authoring UI가 필요하다.
물리 정합성
불확실
PBR texture의 roughness/metallic 값이 측정 pBRDF 후보를 유일하게 결정하지 않는다.
데이터셋 효과
장기
성공하면 가장 강력하지만, 단기 OpticalNav 렌더 품질 문제를 해결하기에는 과하다.

필요한 구조

PBR maps ├─ albedo: 색상/패턴 힌트 ├─ roughness: lobe width 힌트 ├─ metallic: conductor/dielectric routing 힌트 └─ normal: micro-geometry 힌트 │ ▼ Material classifier ├─ per-texel pBRDF_id map ├─ confidence map └─ optional blend weights │ ▼ Mitsuba plugin ├─ 여러 pBRDF table 동시 로드 ├─ UV에서 pBRDF_id/weight sample └─ 선택 또는 보간 후 BSDF eval

핵심 난점

  • pBRDF 선택의 근거 부족: albedo/roughness/metallic은 렌더러용 파라미터일 뿐, 실제 측정 pBRDF id label이 아니다.
  • 보간의 물리성: 서로 다른 측정 pBRDF 테이블을 선형 보간한다고 실제 중간 재질이 되는 것은 아니다.
  • 메모리: 하나의 object 안에서 여러 pBRDF table을 로드하면 channel-split 최적화 이득이 줄고 GPU memory pressure가 커진다.
  • anti-aliasing: UV 경계에서 pBRDF id가 바뀌면 texture filtering과 BSDF sampling이 맞물려 noise/seam이 생길 수 있다.
  • 검증: "최적 pBRDF"가 맞다는 ground truth가 없어 정량 평가가 어렵다.
판정: 구현은 가능하지만 지금 바로 할 일은 아니다. 3안은 별도 연구 주제로 두고, 단기에는 1안의 albedo modulation과 2안의 material slot 분리를 먼저 안정화하는 것이 맞다.

현실적인 축소 버전

3안을 완전히 버리기보다는, 먼저 per-pixel pBRDF가 아니라 per-material-slot classifier로 낮춘다. roughness/metallic map은 pBRDF id를 직접 결정하는 label이 아니라 "금속/비금속", "매끈함/거침" 같은 후보 ranking feature로만 사용한다.

안 핵심 아이디어 구현 가능성 품질 개선 물리적 방어력 권장 위치

권장 로드맵

Phase 0
프로덕션 플러그인 정상화

modules/mitsuba3-optix7 → build/mitsuba3-optix7에 measured_polarized_rgb를 컴파일하고 cuda_ad_spectral_polarized에서 로드 확인.

Phase 1
Texture-modulated measured pBRDF

1안 구현. 기존 base_color texture를 albedo_scale로 보존하고, measured RGB 결과에 곱한다.

Phase 2
Material slot 기반 part mapping

2안의 안전한 범위. 이미 분리된 slot/mesh에만 다른 pBRDF를 붙이고 자동 triangle split은 후순위로 둔다.

Phase 3
PBR map audit / candidate ranking

roughness/metallic/normal map을 pBRDF 직접 선택이 아니라 classifier feature로 사용. material override UI에 추천 후보를 표시한다.

Phase 4
Per-pixel pBRDF map 연구

3안. 별도 plugin prototype과 작은 test asset에서만 검증한다. OpticalNav 본 dataset 일정과 분리한다.

리스크와 판단 기준

리스크영향판단 기준대응
논문에서 "진짜 SV-BRDF가 아니다" 지적 방법론 claim 약화 위치별 pBRDF 변화가 아니라 texture modulation이면 SV-BRDF라고 부르기 어렵다. 용어를 texture-modulated measured pBRDF로 제한한다.
기존 texture가 baked lighting을 포함 물리 기반 렌더 결과가 이중 조명처럼 보임 shadow/highlight가 albedo texture에 이미 들어있는 asset texture audit, asset whitelist, low-frequency illumination 제거 검토
roughness/metallic map 미활용 일부 재질의 micro-appearance 손실 albedo만 살려서는 금속 스크래치/광택 변화가 부족할 수 있음 2단계에서 slot 분리, 3단계에서 candidate ranking feature로 사용
pBRDF table 부족 다양한 asset을 소수 measured material로 반복 매핑 HPBRDF 약 14종 channel mirror, KAIST pBRDF 25종 수준 대분류 중심 매핑을 명시하고 MERL/UTIA/OpenSVBRDF 확장 검토
최종 판단: 6월 17일 기준 작업 순서는 measured_polarized_rgb production build → albedo_scale texture multiplier → slot-level pBRDF override가 맞다. 3안은 매력적이지만 본 dataset 생성의 critical path에 넣기에는 불확실성이 크다.
