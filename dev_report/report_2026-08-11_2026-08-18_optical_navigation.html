1. Modern Office 장면 생성 규칙 및 wizard

관련 커밋: 37cd36d · feat(office): Modern Office OpticalNav 생성 규칙과 wizard를 추가한다

  • 결정적 floorplan 및 room program 생성 규칙을 추가했다.
  • 기본 Modern Office 스타일과 structural-glass 스타일을 분리했다.
  • Infinigen wizard에 안전한 import/export 보조 기능과 content policy·호환성 계층을 추가했다.
  • Structural glass 사용 여부와 graph 품질을 점검하는 audit 스크립트를 추가했다.
  • scene metadata가 생성 규칙과 graph-build 옵션을 보존하도록 graph pipeline·scene sync·sensor sweep을 확장했다.
  • wizard/export layout, floorplan, import 호환성, content policy, graph audit 회귀 테스트를 추가했다.
동일한 입력 설정에서 재현 가능한 office scene을 만들고, 유리 파티션이 포함된 장면을 OpticalNav graph 데이터와 함께 검증할 수 있는 기반을 마련했다.

1-A. Wide Glass Office v2 구현 기능

목표. v2는 기존 compact Office의 확장판이 아니라, 넓은 업무 공간을 결정적으로 생성하고, structural glass·office-only population·OpticalNav graph를 하나의 검증 가능한 계약으로 연결하는 별도 생성 프로필이다. v1의 published seed contract는 변경하지 않는다.

1. Wide floor-plan contract

modern_glass_office_v2는 432–520 m² footprint에서 3–4개의 독립 work bay를 만든다. dual-spine circulation과 meeting 3·focus office 4·reception/support·break·restroom 2·storage 프로그램을 고정하고, 각 work bay는 75 m² 이하로 제한한다.

2. Provenance manifest

office_layout_manifest.json에 logical/effective seed, footprint, bay별 room ID·면적, room program, structural-glass digest와 population policy를 기록한다. 생성 결과와 이후 audit이 같은 layout contract를 보도록 한다.

3. Office-only population

주거용 constraint graph를 재사용하지 않고 office 전용 asset registry와 quota를 사용한다. work bay는 desk/chair/monitor 6–10개, focus·reception은 workstation, meeting·break·restroom·storage는 용도별 최소 구성을 요구한다.

4. Door-preserving structural glass

corridor-facing 벽 중 기존 door opening이 있는 후보에서 10개 partition을 결정적으로 선택한다. 각 partition은 문 양쪽의 두 pane으로 설치되어 총 20 panes이며, 유리 설치가 navigation barrier를 만들지 않도록 한다.

5. Candidate recovery & publish

logical seed에서 attempt별 effective seed를 파생하고, preflight → full generation → workstation layout → Blender population audit을 통과한 첫 candidate만 staging을 거쳐 full/로 atomic publish한다. solver configuration 실패는 무의미한 seed retry로 숨기지 않는다.

6. End-to-end quality gates

preflight는 footprint·bay·glass·asset factory·solver 제약을 검사한다. population audit은 domestic/unassigned asset과 furniture concentration을, graph audit은 pane import·door crossing·각 work bay의 navigable viewpoint를 확인한다.

1-C. 8월 11일 Apartment와 6월 29일 KR Apartment의 wall texture 비교

이번 기간에 추가된 중요한 scene-generation 작업은 infinigen_apartment_20260811의 내부 벽을 더 평탄한 단일 재질에서 벗어나게 만든 것이다. infinigen_gen.py의 작업 기록에 따르면 2026-08-11 Infinigen 설치본에 직접 패치를 적용해, 기존 Plaster + Tile 중심의 wall palette에 Brick과 Wood를 추가하고 feature-wall용 wall_accent 선택지를 확장했다.

두 이미지는 동일 viewpoint pair가 아닌 대표 샘플이므로 정량적인 영상 차이 비교가 아니다. wall material 차이는 scene XML·materialization metadata와 함께 판정한다.

2. Render daemon 및 멀티 GPU 운영

관련 커밋: f31a03f · feat(renderer): OpticalNav daemon 다중 GPU 렌더와 UI 상태를 강화한다

  • daemon의 batch summary, GPU sharding, resume 동작을 보강했다.
  • flash/spectral 처리와 spatial PBR 렌더 경로를 확장했다.
  • navigation_dataset exporter가 새 render 상태와 modality를 전달하도록 갱신했다.
  • Web UI의 dataset 화면, batch helper, render service, rail sensor/scene 탭에서 큐·배치·센서 상태를 표시하도록 조정했다.
  • OptiX 7 queue launcher와 kitchen multimodal/unified harness를 새 상태 계약에 맞췄다.
  • batch summary, sharding, spectral flash, spatial PBR, versioned artifact 회귀 테스트를 추가·갱신했다.

장시간 viewpoint × heading 렌더에서 작업 분할과 재개 상태를 추적할 수 있고, RGB 외 modality를 UI와 export 단계에서 유지할 수 있는 구조가 되었다.

3. OpticalNav 산출물 정리 기준

관련 문서: out_cleanup_inventory_2026-08-18.md

  • out/을 OpticalNav 핵심 데이터, Infinigen import/staging, 렌더·export 결과, 실험·cache·scratch로 분류했다.
  • dataset.json, scenes, episodes, splits, exports, render_ledger.sqlite3를 핵심 보존 대상으로 식별했다.
  • authoring_map → import, scene → authoring_map, dataset.json → scene, export manifest → source, ledger → batch 역참조를 삭제 전 검증 계약으로 정의했다.
  • .retired, .backup, .staging, debug/smoke, 재생성 가능한 cache는 참조와 실행 상태 확인 후 archive/delete 후보로 분류했다.
  • OBJ/MTL/GLB는 확장자만으로 삭제하지 않고 fallback 참조와 재현성 계약을 먼저 확인하도록 했다.

이번 조사는 삭제를 수행하지 않은 읽기 전용 inventory다.

4. 기간 중 연관 작업

7ddb6bc와 2e39ad3의 IR/Principled RGB-Active-NIR 파이프라인은 OpticalNav scene·import·camera pose·material pipeline을 재사용하는 인접 작업이다. 주된 목적은 IR이므로 핵심 기능 목록과 분리했지만, OpticalNav 장면 자산과 렌더 인프라의 품질·재사용성에 영향을 주는 기반 작업으로 기록한다.
