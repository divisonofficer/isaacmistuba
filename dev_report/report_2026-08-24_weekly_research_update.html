1. OpticalNav Polar transport: direct preview → physical path

무엇을 바꿨나 구현 완료

RenderConfig.polar_transport를 도입해 기본값을 physical로 설정했다. 이 모드는 Stokes integrator 내부에 path(max_depth=6)를 사용한다. 따라서 카메라로 들어오는 Stokes 신호에 반사·투과를 포함한 다중 segment transport를 포함할 수 있다. 기존의 빠른 direct(max_depth=2)는 preview 진단 모드로만 유지한다.

이는 depth AOV를 반사에 합성하는 기능이 아니다. 깊이 제한(path-depth-bounded) 경로 추적으로 편광 반사·투과 경로를 계산하는 변경이다.

  • Stokes staging 및 scene-reuse cache key에 nested integrator와 maximum depth를 포함했다.
  • polar pass timing/metadata에 polar_transport, nested_integrator, max_depth, Stokes luminance 통계를 기록한다.
  • 저장된 request에 transport 값이 없어도 새 기본값 physical을 적용하며, 미지의 mode는 거부한다.

통제 검증 설계 테스트 통과 GPU 실행 대기

apps/render_polar_transport_fixtures.py는 finite-thickness dielectric glass window, glass bottle, back-silvered mirror를 생성해 preview/direct와 physical/path를 같은 카메라에서 비교한다. 각 결과는 stokes_data.npz의 finite ratio, invalid pixel count, S0 mean, DoLP mean으로 요약한다. thin dielectric을 쓰지 않고 유한 두께의 dielectric과 Ag conductor를 사용해 반사·투과 회귀를 겨냥한다.

이번 점검에서는 관련 Polar transport와 fixture, IR contract 테스트를 합쳐 20 passed를 확인했다. 이는 configuration/staging/fixture 정의의 회귀 방지 근거이며 GPU renderer의 물리적 개선 결과는 아니다.

2. IR dataset: specular object distribution

소품 composition 계약 구현 완료

inverse_rendering_showcase_v1은 audited native asset registry에서 seed로 결정론적 selection을 만든다. composition 하나는 16–24개의 소품, 최소 8개의 semantic category, factory별 최대 2개라는 제약을 만족한다.

배치는 support surface의 여유 공간·occlusion·multi-view potential을 점수화하고, 충돌하지 않는 lattice position을 선택한다. native support가 부족하면 visible neutral display bench를 명시적 scene geometry로 추가하며 manifest에 이를 남긴다.

3. IR dataset: render diversification and camera viewpoints

조명 다양성 구현 완료

render plan은 정확히 6개의 illumination condition을 사용한다. 선택 포즈의 25%는 모든 조명 조건에서 같은 카메라 pose로 렌더하는 paired capture이고, 나머지는 공간 coverage를 유지하는 single capture로 각 condition에 분배한다. 이 방식은 조명 변화의 비교 가능성과 scene coverage를 함께 유지하며, plan에는 condition asset, recipe digest, pair ID, expected frame count를 남긴다.

카메라·가시성 계약 구현 완료

  • 각 target anchor를 향하는 4–12개 multi-view set을 walkable graph node에서 고른다. 임의의 기존 heading sweep을 되살리지 않고 anchor 방향 yaw/pitch를 계산한다.
  • camera clearance ≥0.4 m, forward clearance ≥1.0 m, anchor distance 1.2–4.5 m, set 내 baseline ≥0.5 m, azimuth span ≥90°를 적용한다.
  • scene-scale acceptance는 조명 frame 수와 별개로 최소 50개의 독립 physical pose를 요구한다. strict anchor set이 부족하면 동일 안전 후보군에서 coverage-only supplemental pose를 추가하되 multi-view tuple로 위장하지 않는다.
  • 160×120-equivalent raster probe는 object/material ID, depth, normal, roughness, metallic, base color를 보고, weak set을 immutable render plan 이전에 제외한다. set acceptance에는 shared object ≥8, union object ≥12, severe occlusion/near-wall 부재, target의 최소 2-view 관측을 사용한다.
